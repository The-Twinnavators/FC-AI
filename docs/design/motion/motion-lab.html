Every pattern below is live. It uses only the browser's own CSS transitions, the Web Animations API, native <dialog> and View Transitions, with no animation package. Functional · all levels

Button and control feedback

The press shows the instant the pointer goes down, not after a delay. Toggles move with a short spring that can be interrupted mid-way: clicking quickly ends on the right state, never on a finished animation for the wrong one.

Flat presses with a tint and a tiny scale; Tactile also drops its shadow and moves 1px.

Use for
Every pressable thing: buttons, switches, checkboxes, chips, rows.
Avoid
Bouncy scale on large surfaces, any delay before the pressed state, hover motion on touch.
Native
CSS transitions on scale/translate/background-color; linear() for the spring.
Library
No real gain.
Reduced
No scale or travel; colour change only (90ms).
Tests
Rapid toggling ends on the clicked state; Space/Enter work; focus ring visible; no layout shift (transform only).

Save and selection state

Saving acknowledges the click at once. The spinner appears only if the save takes more than 150ms, so fast saves don't flash. Clicks during a save are coalesced into one more save, never lost and never queued ten deep. The result is announced to screen readers.

Functional · all levels

Dialogs and drawers

These are native <dialog>s. The browser handles the focus trap, Escape and returning focus, and CSS animates both entry and exit. Every control inside works from the first frame, and closing is never held up by an exit animation.

Open, then press Escape at once, or click open and close quickly: the state always follows the last action.

Use for
Confirmations, short forms, side panels for filters or details.
Avoid
Zooming from the clicked element on every open; long exits; animating the page behind.
Native
<dialog> + @starting-style + transition-behavior: allow-discrete (exit). Older browsers: no animation, same behaviour.
Library
No.
Reduced
Fade only, no slide or scale.
Tests
Open → Escape immediately → closed and focus back on the opener; Tab stays inside; the drawer's first field is usable at once.

Page transitions

The page changes at once and the browser animates between snapshots, so nothing waits. Focus moves to the new page's heading. Back and Forward work and reverse the direction. A second click mid-transition skips to the latest page.

HomeMy listStores

Use for
Moving between the app's screens; master → detail; wizard steps.
Avoid
Animating the whole document (sticky bars jump); transitions longer than ~350ms; blocking clicks until finished.
Native
document.startViewTransition (same-document). Unsupported browsers change instantly.
Library
No. (React Router already supports View Transitions.)
Reduced
A short crossfade, no slide.
Tests
Back/Forward render the right page; focus on the new heading; 3 quick clicks end on the last; scroll position as expected.

Functional + expressive · amount by level

Card entrance and interaction

Cards that are already visible never animate in. Cards below the fold enter once as they scroll into view, with a capped stagger, and the featured card uses a different motion. Re-rendering the list doesn't replay anything. Hover and press follow the surface style.

Nothing should replay.
Use for
Content arriving for the first time: search results, a dashboard's tiles, a homepage section.
Avoid
Animating every card identically; replaying on re-render; hiding cards in view until JS runs; staggering 40 items.
Native
IntersectionObserver + CSS keyframes; stagger capped at 6 steps.
Library
No.
Reduced
Fade only; Minimal: fade only.
Tests
Above-the-fold cards visible on first frame; re-render replays nothing; every card visible within 1s even if the observer never fires.

Functional · all levels

Filtering and sorting continuity

Items keep their identity while they move, so you can follow where a product went. The list itself updates immediately, so a screen reader or a test reads the new result at once. A rapid change interrupts the move from wherever the items are.

Use for
Filter chips, sort, reorder, add/remove from a list.
Avoid
Fading the whole list out and in (loses continuity); moving 200 items (limit to what's on screen).
Native
FLIP with the Web Animations API: the new results paint first, then items glide. (A view transition per press delayed the response on a slow phone: measured.)
Library
Small: Motion's layout does this in React, but native covers it.
Reduced
Instant reorder with a short fade.
Tests
3 chips clicked in 100ms → list matches the last; count announced; keyboard focus stays on the chip.
